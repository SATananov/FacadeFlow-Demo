# REAL DATA BATCH 01 — WP78.3.1 Project ↔ System Evidence Link

## Purpose

Link the already-existing Nadежда / Вадим-2 SkyGlazing evidence to the WP 78 real-data source record without duplicating the XML/LTE evidence and without automatically confirming a system or role.

## Source boundaries

### WP 78 role source

The real source sheet establishes these source literals and roles:

- `78,01` — Каса / FRAME
- `78,33` — Делител / MULLION
- `78,22` — Крило прозорец / SASH

The punctuation is preserved exactly as supplied by that source.

### Existing Вадим-2 evidence

FacadeFlow already contains locked evidence for project `Вадим-2`, generated by SkyGlazing, with project literals:

- `78.01`
- `78.27`
- `78.33`
- `78.51`

This slice imports that existing evidence in code. It does not copy the XML/LTE dataset into another static evidence source.

## Deterministic bridge result

Evidence-link normalization is deliberately narrow: comma and dot decimal separators are made comparable for linking, while both original literals remain stored on the link row.

Expected cross-source result:

- `78,01` ↔ `78.01` — exact evidence-code match; source role remains Каса / FRAME.
- `78,33` ↔ `78.33` — exact evidence-code match; source role remains Делител / MULLION.
- `78,22` — source-only; no matching Вадим-2 project code.
- `78.27` — project-only; role remains UNCONFIRMED.
- `78.51` — project-only; role remains UNCONFIRMED.

## Critical safety boundary

Two cross-source code matches are evidence that `Вадим-2` is a candidate match for WP 78. They are not automatic proof of system identity.

Therefore this slice keeps:

- `candidateStatus = CANDIDATE_REQUIRES_HUMAN_CONFIRMATION`
- automatic system confirmation disabled
- automatic role inference disabled
- XML `MaxY` / `MaxZ` semantics not promoted to confirmed catalogue dimensions
- catalogue selection disabled
- rules validation disabled
- machine readiness disabled
- production approval disabled

PASS requires all focused tests and existing WP78 / Надежда regressions to pass, lint to report zero errors, and the production build to succeed.
